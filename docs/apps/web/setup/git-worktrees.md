# Git worktrees

Worktrees let you check out several branches into separate folders that share one
`.git` — handy for reviewing a PR, running two features side by side, or letting a
coding agent work in isolation. In **this pnpm + Turborepo monorepo** a bare
`git worktree add` gives you a worktree that **won't build**, because everything a
build needs is gitignored and so is never carried into the new worktree:

| What | Why it's missing in a fresh worktree |
| --- | --- |
| `.env*` (Sanity project id / dataset / token) | gitignored (`.env*`, except `.env.example`) — untracked, so `git worktree add` doesn't copy it |
| `node_modules` | per-worktree; needs its own `pnpm install` |
| `.next` / `.turbo` | per-worktree build output — regenerated, fine |

What **is** shared and makes this cheap: the **global pnpm store**
(`~/Library/pnpm/store`) and the **Turborepo cache** — so a worktree's `pnpm install`
is mostly hardlinks and its builds hit the cache.

## The one command

```bash
scripts/worktree.sh <branch> [path]
```

It creates the worktree **outside** the repo (a sibling dir, so it never nests in the
tracked tree), copies every gitignored `.env*` into it, and runs `pnpm install`. When
it finishes the worktree is ready to `pnpm dev` / `pnpm build`.

```bash
scripts/worktree.sh fix/footer          # → ../indiecrafts-template--fix-footer
cd ../indiecrafts-template--fix-footer
pnpm verify:quick                       # tsc + lint
```

## Manual checklist (if you don't use the script)

1. `git worktree add ../<name> <branch>` (or `-b <branch>` for a new one) — **outside** the repo.
2. **Copy the env**: `cp .env.local ../<name>/code/apps/web/.env.local` (and any other `.env*`). Without it, Sanity reads fail and the build errors.
3. `cd ../<name> && pnpm install`. If it fails on a recently-published package, the repo's `minimumReleaseAge` policy is blocking it — run `pnpm install --config.minimumReleaseAge=0` (a per-install override; it doesn't touch the committed config). Husky hooks (`.husky/`) are regenerated by the install's `prepare` step.
4. Verify: `pnpm verify:quick` (or `pnpm build`).

## Clean up

```bash
git worktree remove ../<name>   # delete the folder + its registration
git worktree prune              # drop stale entries (folders deleted by hand)
git worktree list               # confirm what's registered
```

## Notes

- **Never put a worktree inside the repo** — it would nest a checkout in the tracked
  tree. Keep them as siblings (the script does this).
- **Agent worktrees** (the coding-agent `isolation: "worktree"` mode) are for isolated
  *code edits*; they inherit the same gitignore gaps, so a full `pnpm build` there needs
  the `.env*` copied in the same way.
- One `pnpm store` + one turbo cache across all worktrees → installs and builds stay fast;
  don't set a per-worktree store.
