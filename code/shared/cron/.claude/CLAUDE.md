# @indiecrafts/shared-cron — scheduled worker

Auto-loads under `code/shared/cron/**`. A **bare Cloudflare Worker** (no Next/OpenNext) that runs on a schedule. This file is the app's _how to code_; platform rules live in the root `CLAUDE.md`.

**Stack:** Cloudflare Workers (`workerd`) · TypeScript · wrangler 4. A thin deploy shell — the scheduled task is imported from packages/modules, not written here.

`scheduled()` runs three passes on the api's two EU D1s (both `--location weur`, both
bound directly — same `database_id`s the `api` worker uses): `DB` (`audit` — the firehose,
`admin_audit`/`session_events`/`security_events`/`csp_reports`) and `MAIN_DB` (`main` —
identity/rights/settings, `consent_events`/`data_requests`/`erasure_requests`/
`export_requests`/`site_settings`). The three passes: the 90-day/3-year retention purge
(split per binding — audit tables on `DB`, `consent_events`/`data_requests`/
`erasure_requests` on `MAIN_DB`), an erasure-SLA flag (flags a `MAIN_DB` `erasure_requests`
row nearing or past its GDPR one-month `due_at` with a `DB` `security_events` row, once, via
`due_flagged_at`), and an expired-export cleanup (deletes a `MAIN_DB` `export_requests` row

- its object in the api's `EXPORT_BUCKET` R2 bucket once its 1-hour TTL passes unread). Each
  pass is inline, pure helpers + a try/catch that logs and rethrows — no separate job files.

## Structure

```
src/index.ts       entrypoint — `export default { scheduled, fetch }`
wrangler.toml      per-env config + `[triggers] crons`; `name = indiecrafts-cron-<env>`
src/index.test.ts  colocated Vitest in workerd (vitest-pool-workers) — health + `scheduled`
worker-configuration.d.ts   generated by `pnpm cf-typegen` (typed bindings)
```

## Critical rules (the NEVERs)

- NEVER put the task logic here — import it from a `code/packages/<name>` / `code/modules/<name>` brick (`workspace:*`). This app is the **deploy shell** only.
- NEVER hand-edit the `indiecrafts-cron-*` names in `wrangler.toml` — `pnpm project:rename <slug>` owns them; a staging/prod deploy is blocked until they differ (shared-account guard).
- NEVER let a scheduled failure pass silently — `logger.error(...)` + rethrow so the run is marked failed and retried.
- ALWAYS keep the schedule in `[triggers] crons` (UTC); test locally with `wrangler dev` → `curl localhost:8787/__scheduled`.

## Deploy

**Platform class:** `worker-cf` (a bare Worker). `pnpm deploy:shared:cron:<dev|staging|prod>` → the shared `shared/scripts/deploy/worker.mjs` (rename guard + prod-confirm + `wrangler deploy`); or `pnpm deploy:all:<env>` (every Cloudflare app). Bare `wrangler deploy` bundles `src/` + imports — no build step. A cron worker needs no domain/WAF, so it needs no Terraform dir (unlike the web app). It's a row in [`scripts/lib/apps.mjs`](../../../shared/scripts/lib/apps.mjs), the source of truth CI + deploy read — so CI deploys it automatically, no per-app workflow.
