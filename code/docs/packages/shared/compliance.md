# `@indiecrafts/packages-shared-compliance` — the portable compliance core

The half of the compliance surface every web surface can share: the consent decision math, the
store contract, the legal-route contract, and a consent + legal-re-acceptance UI.
Lives in **`code/packages/shared/compliance`**, consumed as source. **No `next`/Sanity**
— the website keeps its richer Sanity/next-intl banner
([`@indiecrafts/packages-web-compliance`](/packages/web/compliance)) over the same math; this brick
serves the `app` web surface (the Capacitor shell loads that same surface).

Extracted so the `app` surface reaches the website's canonical legal pages + ships a compliant-ready
consent UI out of the box, instead of re-implementing a bespoke banner.

## Exports — `./shared` + `./web`

`./shared` = the platform-agnostic core (no React/DOM). `./web` = the DOM (shadcn)
components + a `localStorage` store adapter (**Next-free** — serves the plain-React `app`
surface).

## Confirmation toast + a settings control (surface-owned)

`ConsentBanner`/`ConsentPreferences` stay copy-in, no-toast — each shell fires the confirmation
itself after persisting an **explicit** choice (accept/reject/save) or a legal re-acceptance, via
`showConsentSavedToast` (`@indiecrafts/packages-web-ui-components/web/consent-toast`). The silent
geo auto-seed effect never calls it. Each shell's toast `onManage` opens its own
cookie-preferences control, built from this brick's `ConsentPreferences` over the same
`Store` key the banner reads: the `app` web surface at `/account`.

## The split (this brick vs the web brick vs the app)

- **`packages-shared-compliance`** owns the portable math + the copy-injected UI + the store adapter.
- **[`packages-web-compliance`](/packages/web/compliance)** (website only) keeps the Sanity-driven cookie inventory, the next-intl `CookieBanner`, the legal-page **content** (`LegalPageContent`), the GDPR data-request flow, and the Sanity schema. It re-exports the moved `consent-signals` (unchanged import path) and imports `grantedKeys`/`consentUpdate`/`ConsentRecord` from here (one source of truth for the math).
- **Each web surface** injects copy from its `messages`, wires a store adapter, gates the banner on a `requireConsent` flag, and passes a `site.websiteUrl` base to `legalUrl` for the link-out. See [Mobile shell](/shared/architecture/cross-platform-shell).

## Cross-surface legal re-acceptance

The `./shared` transport unifies the "policies updated" banner across website · app (the Capacitor shell loads `app`):

- **One version.** `fetchLegalVersion(websiteBaseUrl)` reads the website's `/api/legal-version` route (`LEGAL_VERSION_ENDPOINT`), which returns the **same** string the website banner computes. The `app` gate uses it as the effective version — the static `policyVersion` is only the offline fallback — so **one Sanity bump re-prompts every surface** (no per-surface version edit).
- **Signed-in sync.** `readLegalConsent({apiUrl, getToken})` / `writeLegalConsent({apiUrl, getToken, version, surface})` call the api Worker's [`/v1/consent/legal`](/shared/api/) route (Clerk-JWT). On mount a signed-in gate reads the server-recorded version and, if it matches, deposits it locally so the banner never shows; on Accept it records the version, so **accepting on one surface clears the banner on all**. Both are best-effort (return `null`/`false` on any failure) — the per-surface local deposit still hides the banner. `syncLegalConsent({…, version, surface, acceptedHere})` runs on every signed-in load: it reads the server record and, when the user accepted this version **here** but the write was lost (a reload, offline, a failed token refresh), sends it again — never accepting on the user's behalf.
- **Anonymous** visitors keep their per-surface local deposit only (cookie on the website, `localStorage` on `app`) — two origins share no identity to sync by.

## Gotchas

- **`legalUrl` mirrors the website's `as-needed` prefix policy** (default locale unprefixed, others `/<code>`) via `localizedPathname`, so the URL matches the live route. It falls back to the default-locale slug for a locale with no legal slug yet.
- **`LEGAL_PAGES` is `as const`** so its literal `key`/`id`/`slug` survive being spread into the website's `pages` map (which derives its typed route union from the literal `key`s). The website's `pages.ts` spreads `...LEGAL_PAGES.<key>` + adds `enabled`.
