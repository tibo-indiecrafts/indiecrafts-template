# D1 erasure adapters

> Pseudonymise identity and consent in the core D1; delete or pseudonymise the audit firehose.

## Purpose

Implements the two D1 erasure adapters, split across the `main` (core) and `audit` D1s. The core adapter pseudonymises `user_profiles` and `consent_events` and hard-deletes `email_preferences`. The audit adapter deletes `session_events`, pseudonymises high/critical `security_events` and deletes every other severity, and retains `admin_audit`. The audit adapter has no identity table of its own, so it resolves the subject by reading `core.user_profiles` first. A newsletter consent row (`visitor`, `subject_id` = `email_fingerprint`) is born in the pseudonymised form; `export` finds it by fingerprint, with or without a profile.

## Exports

- `resolveSubject(coreDb, email, salt)` — resolves the Clerk `user_id` and email fingerprint from `core.user_profiles`, falling back to a plaintext email match.
- `createCoreErasureAdapter(coreDb, salt)` — the `d1-core` adapter (identity + consent pseudonymise, `email_preferences` delete).
- `createAuditErasureAdapter(auditDb, coreDb, salt)` — the `d1-audit` adapter (session/security firehose), reading core to resolve the subject.

## Usage

```ts
import {
  createCoreErasureAdapter,
  createAuditErasureAdapter,
} from "@indiecrafts/api/erasure/d1";

const core = createCoreErasureAdapter(env.MAIN_DB, env.GDPR_FINGERPRINT_SALT);
const audit = createAuditErasureAdapter(
  env.AUDIT_DB,
  env.MAIN_DB,
  env.GDPR_FINGERPRINT_SALT,
);
```
