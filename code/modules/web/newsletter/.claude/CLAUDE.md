# Newsletter module — CLAUDE.md

**Stack:** TypeScript · `@indiecrafts/packages-shared-gated-delivery` (HMAC) · `@indiecrafts/packages-web-email` · Sanity v6 (settings + lead magnets only). The newsletter feature — sign-up + signed double opt-in + lead magnets + settings singleton.

Auto-loads under `code/modules/web/newsletter/**`. Feature-flagged by `features.newsletter` (app-owned in `@/config`, injected into the module — see below).

- **Resend is the only subscriber list.** Nothing is stored at sign-up. The confirm click calls the api (`lib/newsletter-contact.ts` → `POST /v1/newsletter/subscribers`), which records the consent proof in D1 and upserts the Resend contact (`news` topic, `locale` property, `newsletter-<locale>` segment). Unsubscribe is Resend's own link. No per-ESP adapters; an external ESP uses its own embed form in a `custom-html` block (add its host to `EMBED_HOSTS`).
- `src/lib/newsletter.ts` — `subscribe()`: validate → sign the sign-up (`signConfirmToken`) → email the confirm link in the visitor's language. Every real sign-up answers the same (no membership oracle). A missing secret, Resend key, confirm email or api → `unavailable` (the route answers 503), never a silent drop. `LEAD_MAGNET_SOURCE` marks a lead-magnet-only request (`newsletter: false` — its consent covers the document). Feature-gating is the **app's** job (`/api/newsletter*` routes; `newsletterSanity(enabled)` hides the desk).
- `src/lib/confirm.ts` — `signConfirmToken` / `verifyConfirmToken` (payload signed with `NEWSLETTER_SECRET`, valid `CONFIRM_TOKEN_DAYS` = 7) and `confirmSubscription(token)`: a newsletter sign-up → the api (failure = `error`, nothing confirmed), then lead magnets, then the owner alert. Called by the **POST** `/api/newsletter/confirm` route; the email links to `[locale]/newsletter/confirm#t=<token>` — the token rides in the URL fragment (never sent to a server) and only a button tap POSTs it.
- **Email config + copy** live on the shared `emailStrings` singleton (Studio → **E-mails**) — `newsletterConfirm` (required, translated) · `newsletterOwner` (on confirm) · `leadMagnet`. Read via `getEmailStrings()` from `@indiecrafts/packages-web-email/strings`. **Secrets:** `RESEND_API_KEY` + `NEWSLETTER_SECRET` (signs the confirm link and the download link).
- **Email templates** live in `src/emails/` (`newsletter-confirm` · `newsletter-notification` · `lead-magnet`) — each renders via `@indiecrafts/packages-web-email`'s `renderEmailLayout`/`escapeHtml`; English/French fallback copy, English for other locales.
- `src/lib/settings.ts` — `getNewsletterSettings()` (React-`cache`d) reads the `newsletterSettings` singleton (form copy + `enabled`).
- `src/sanity/` — the `newsletterSettings` singleton + the `leadMagnet` doc + the desk (`newsletterStructure`), exported as the `newsletterSanity(enabled)` **`SanityModule`** factory barrel. Activate = `newsletterSanity(features.newsletter)` in `appModules` (`sanity.config.ts`).
- The public **form is a page-builder block** (`module.newsletter` / `module.lead-magnet` schemas in `@indiecrafts/packages-web-page-builder`, renderers in `@indiecrafts/packages-web-ui-components`) that POSTs `/api/newsletter` (a thin app route → this module's engine).
- **Lead magnets (gated delivery).** A `leadMagnet` doc (Studio) pairs a `tag` with an uploaded file. On confirm, each tag that is a magnet's id gets a **signed, expiring download link** (`src/lib/deliver-magnet.ts` → `@indiecrafts/packages-shared-gated-delivery`); `/api/download` verifies it (`resolveMagnetDownload`).
